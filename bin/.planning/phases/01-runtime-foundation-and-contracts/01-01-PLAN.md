<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| analysis request -> runtime planner | Untrusted file/type inputs influence adapter selection and error surfaces |
| config.yaml -> runtime contracts | Operator-provided values influence mode, timeout, and fallback behavior |
| adapter lifecycle -> result envelope | Process/runtime state crosses into externally visible diagnostics |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `analysis_plan_builder` mode resolution | mitigate | Validate allowed runtime mode enum and reject unknown values with typed `CONFIG_INVALID` code |
| T-01-02 | Information Disclosure | `error_taxonomy` and normalized diagnostics | mitigate | Enforce curated remediation payload fields and avoid leaking raw paths/secrets/process args |
| T-01-03 | Denial of Service | `state_machine` timeout transitions | mitigate | Require bounded startup/probe timeout states with deterministic transition to `DEGRADED` or `FAILED` |
| T-01-04 | Repudiation | `result_normalizer` failure envelopes | mitigate | Include stable error code and state identifier in all failure responses for deterministic auditability |
</threat_model>
